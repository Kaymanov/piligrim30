# SEO: управление и запуск

Основной домен: **https://piligrim30.ru**. Тестовый домен: **https://test.piligrim30.ru**.
Приоритет: банкротство физических лиц и списание долгов в Астрахани и Астраханской области.

## Что реализовано

- В Django Admin появился раздел «Поисковое продвижение (SEO)».
- «Общие настройки SEO»: общий запрет индексации, описание и изображение по умолчанию,
  подтверждение Google Search Console / Яндекс Вебмастера, данные организации, регион, IndexNow.
- «SEO статических страниц»: title, description, canonical, index/follow, Open Graph,
  поддерживаемые типы микроразметки для всех 14 статических маршрутов.
- Статьи и кейсы используют существующие SEO-поля собственных карточек в админке.
- Настройки выводятся сервером в HTML. Отдельная сборка для изменения SEO не требуется.
- Статьи получают Article/BlogPosting/NewsArticle, статьи и кейсы — видимые хлебные крошки
  и BreadcrumbList. Название сайта размечено WebSite. При заполнении организации, адреса
  и телефона выводится LegalService. Эти сведения должны совпадать с видимыми контактами.
- Sitemap строится по опубликованным индексируемым страницам. Страницы с canonical на
  другой адрес исключаются. `lastmod` использует дату записи, а неизвестная дата опускается.
  Google игнорирует sitemap priority/changefreq, поэтому эти поля не используются как
  механизм продвижения.
- Несуществующие статьи и кейсы используют notFound; общий loading вынесен на главную,
  чтобы не отправлять HTTP 200 до проверки существования документа.
- Ошибка сервера контента не маскируется под удалённую статью.
- Список статей формируется на сервере из опубликованных записей, без демонстрационных ссылок.
- IndexNow при включении сообщает Яндексу о публикации, изменении адреса, архивировании
  и удалении материалов. Задача отправляется после фиксации транзакции и повторяется при
  сетевой ошибке. Сбой очереди записывается в серверный журнал и не прерывает сохранение.

## Приоритет источников

Для статических маршрутов: отдельная запись «SEO статической страницы» → опубликованная
услуга с совпадающим slug → опубликованная Page с совпадающим slug → существующий заголовок
и описание в интерфейсе. Отдельная SEO-запись полностью переопределяет SEO соответствующей
услуги/страницы; пустые заголовок и описание используют значения интерфейса.

SEO-запись не создаёт новую страницу и не меняет её адрес. Адрес выбирается из существующих
маршрутов. Статьи и кейсы редактируются в своих разделах, без дублирующих SEO-записей.
H1 статьи по-прежнему задаётся в её карточке; H1 и основной текст большинства статических
страниц остаются частью интерфейса. Свободный конструктор посадочных страниц сюда не входит.

Поле schema_type не принимает произвольный HTML/JavaScript. Для статических страниц
выводятся WebPage, CollectionPage, ContactPage, Service. Для статей поддерживаются Article,
BlogPosting и NewsArticle; по умолчанию Article. Кейсы используют WebPage.

## Развёртывание

1. Применить миграции Django до запуска нового фронтенда:
   `python manage.py migrate` (в существующем Docker entrypoint это уже выполняется).
2. Задать окружение отдельно для каждой площадки:
   - основной сайт: `SITE_URL=https://piligrim30.ru`;
   - тестовый: `SITE_URL=https://test.piligrim30.ru`.
   При отсутствии SITE_URL индексация фронтенда закрыта. Переменная читается во время
   работы сервера, поэтому настройка окружения не зависит от сборки NEXT_PUBLIC_*.
3. Указать доступный для Next.js `INTERNAL_API_URL`, запустить backend и frontend.
   SEO API необходим для рендеринга страниц; ошибка API должна давать серверную ошибку,
   а не подменять редакторские настройки. Страницы рендерятся по запросу; общий CDN-кэш HTML
   необходимо согласовать с требованием обновления настроек.
4. Создать общие SEO-настройки в админке. Заполнить реальные данные организации.
5. Добавить основной сайт в Google Search Console и Яндекс Вебмастер. Вставить значения
   content из тегов подтверждения в соответствующие поля админки. Отправить
   `https://piligrim30.ru/sitemap.xml` в обоих кабинетах.
6. Для IndexNow создать ключ из 8–128 латинских букв, цифр или дефисов. Задать одинаковый
   `INDEXNOW_KEY` backend и frontend; проверить `https://piligrim30.ru/indexnow-key.txt`.
   Запустить существующий Celery worker и включить IndexNow в общих SEO-настройках.
   На тестовой площадке уведомления и выдача ключа отключены независимо от флага админки.
7. Проверить живой основной домен в инструментах поисковиков: доступность HTML, canonical,
   robots, sitemap и мобильный вариант. Конфигурация Nginx и доступ к серверу в репозиторий
   не входят. Поле запрета индексации действует через meta robots, а не Disallow, чтобы
   поисковый робот мог прочитать noindex на уже известной ему странице.

## Как получать органический трафик

Автоматизация обслуживает публикации, но не гарантирует обход, включение в индекс или позиции.
Для юридических материалов необходимы конкретный автор, проверка содержания и обновление
при изменении законодательства. Публиковать полезные материалы по отдельным задачам клиентов
и связывать их с услугами, а не создавать десятки одинаковых страниц под варианты запросов.

Стартовые тематические группы (без оценки частотности и конкуренции):

| Тема | Существующая основная страница | Содержание для развития |
| --- | --- | --- |
| Банкротство физлиц в Астрахани | /bankrotstvo-fizicheskih-lic | Условия, документы, этапы, автор, реальные кейсы |
| Списание долгов | /spisanie-dolgov | Виды долгов, ограничения, разбор ситуаций |
| Сопровождение под ключ | /bankrotstvo-pod-klyuch | Состав услуги, фактическая стоимость, договор |
| Внесудебное банкротство | /bankrotstvo-cherez-mfc | Актуальные условия и пошаговое объяснение |
| Имущество и последствия | /blog | Экспертные ответы с датой проверки и ссылками на источники |

Показы, запросы, переходы и средние позиции проверяются в Search Console и Вебмастере;
заявки — в аналитике и Django. Учётные записи, Метрика/GA и импорт их отчётов в админку
этой доработкой не подключаются. Существующие Django-редиректы также требуют отдельного
подключения к обработке URL во фронтенде или Nginx перед переносом адресов старого сайта.

## Проверки

- Backend: `python manage.py test apps.seo.tests --settings=core.test_settings`.
  Используются SQLite в памяти и локальный кэш. Внешние уведомления замоканы.
- Миграции: `python manage.py makemigrations --check --dry-run --settings=core.test_settings`.
- Frontend: `npm run build -- --webpack`, `npx tsc --noEmit`.
- Перед выпуском: HTTP-проверка главной, услуги, статьи, несуществующего slug, страницы
  с noindex, robots.txt и sitemap.xml на основном и тестовом окружениях.
